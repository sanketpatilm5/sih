Bhoomi3D · hands-on walkthrough

Draw it flat. Get it back as property.

What the software is, what it is made of, and exactly where you upload a 2D plan to get a 3D register with ownership and identifiers. Written for someone who has not seen the code.

01 · The idea

One polygon, one level, one height

The entire system rests on a single equation. Everything else — the identifiers, the validation, the 3D viewer — is built on top of it:

Today a land record can describe the plot — the outline on the ground. It cannot describe the flat on the eighth floor, the parking bay below it, or the water main under the road, because all three sit at the same ground coordinates. Stack the equation above and you can describe every one of them separately.

Say it like this

"We take the 2D plans that already exist, add the floor levels, and turn every flat, shop and parking bay into a 3D volume with its own number."

02 · Two ways in

Plan upload, or drone survey

Both roads end at the same register. They differ in what they can tell you — and the second one is why the project has an AI component at all.

What you supply A JSON file of polygons and floor heights A LAS/LAZ point cloud, orthophoto, GNSS control
Who has it Every municipal building-permission office Survey contractors; SVAMITVA drone programme
Time to run under 1 second ~17 seconds per city block
What it tells you The sanctioned state — what was approved on paper The as-built state — what is actually standing
Can it find unauthorised floors? No. Nothing contradicts the plan. Yes. It measures the building independently.
Code path plan2d.build_register() pipeline.run_pipeline()
Status Just built — new Already working
Same register, same identifiers, same validation, same viewer. Only the source of the polygons differs.

Why both matter

The 2D path is what a tehsil office can run this afternoon with data it already holds. The survey path is what catches the builder who added a twelfth floor to an eleven-floor sanction. Run the first to build the record; run the second to check it against reality.

03 · Tech stack

What it is made of

BackendPython 3.12, FastAPI, Uvicorn Standard and reviewable. FastAPI generates the interactive API docs from the code itself.
GeometryShapely, NumPy Every property is a prism — a polygon swept between two heights — so overlaps and clearances come out exact without a mesh library.
Coordinatescustom WGS-84 / local ENU Written directly so there is no PROJ or GDAL to install. Metres in, latitude/longitude out.

04 · The 2D → 3D walkthrough

Where to upload, and what happens

Start the software, then open http://127.0.0.1:8000/ and click the 2D → 3D tab on the right-hand side. That tab is the upload point. Five steps, start to finish. 

# start it (Windows)
.venv/Scripts/python scripts/serve.py

# macOS / Linux
.venv/bin/python scripts/serve.py

Take a sample plan

In the 2D → 3D tab, press Simple plot or Housing society. Both are also already on disk in the samples/ folder, along with a drawing of every floor. 

python scripts/make_samples.py

samples/plan-simple.json      ← edit and upload this
samples/plan-society.json     ← or this
samples/plan-simple-f1.svg    ← a drawing of floor 1

Edit it — this is the “2D diagram”

Open the file in any text editor. Coordinates are plain metres from a corner of the site; [8, 6] means 8 m east, 6 m north. Change the numbers to match your building.

The plan file

{
  "site": {
    "name": "Demo Plot",
    "origin": { "lat": 18.52043,
                "lon": 73.856744 }
  },
  "parcels": [{
    "id": "P-01",
    "owner": "Sharda Society",
    "boundary": [[0,0],[44,0],
                 [44,32],[0,32]]
  }],
  "buildings": [{
    "id": "B-01",
    "floors": [{
      "level": 1,
      "repeat_to": 3,      // floors 1-3
      "height": 3.0,
      "units": [{
        "name": "FLAT-{n}01",
        "owner": "Owner {n}01",
        "boundary": [[8,6],[21,6],
                     [21,26],[8,26]]
      }]
    }]
  }]
}

What that draws

Green dashed = the parcel boundary. Amber = flats on this floor. Red dashed = the water main running underground. The grid is 10 m.

The shorthand that saves the most typing

"repeat_to": 3 means “levels 1 through 3 are identical”. {n} in a name becomes the floor number, so FLAT-{n}01 gives FLAT-101, FLAT-201, FLAT-301. A ten-storey tower is one block of text, not ten copies.

Choose the file — it checks before it builds

Press Choose a plan file and pick your edited JSON. The software immediately draws every floor back at you and reports what it found. Nothing is built yet. 

1 parcels   1 buildings   5 storeys   9 units   1 corridors
Plan looks valid — 9 units across 5 storeys

If something is wrong, it says exactly what and where, in plain language, before you waste time on a build: 

building B-01, level 2, unit FLAT-201:
  a boundary needs at least 3 corner points, got 2

building B-01, level 0: floor height 300 m is outside
  the plausible range 1.8-12 m. Heights are in metres.

Press Build 3D register

Every unit polygon is swept through its floor's height range, given an identifier, and slotted into the ownership hierarchy. Then the whole register is validated. This takes under a second. 

Built 83 objects with 83 ULPINs — no defects

Explore what came out

The viewer reloads with your building in it. Click any flat and the inspector shows its identifier decoded field by field, its area, its volume, its height range and its owner.

Then switch on Column probe and click the ground. You get every object in that vertical column — air rights on top, ten floors of flats, the shops at grade, two basement levels, and the metro tunnel underneath. That list is the thing a 2D record cannot produce.

05 · What comes out

The register

Uploading the housing-society sample produces 83 objects, each with its own identifier, arranged in a hierarchy that mirrors how ownership actually works: 

P-01  parcel — Ganga Co-op Housing Society
 └─ B-01  building — Ganga Residency
     ├─ B-01/L-02  basement 2   → PARK-B2
     ├─ B-01/L-01  basement 1   → PARK-B1
     ├─ B-01/L+00  ground floor → SHOP-01, SHOP-02, SHOP-03
     ├─ B-01/L+01  floor 1      → FLAT-101 … FLAT-106
     ┊   ⋮
     └─ B-01/L+10  floor 10     → FLAT-1001 … FLAT-1006
 └─ B-01/AIR  air rights — 30 m column above the roof

INF-METRO-01  metro tunnel — crosses the site at −15.4 m
INF-WATER-01  water main   — 2.0 m below ground

And it is checked. Ten rules run over the whole thing:

  • Overlapping ownership — two units claiming the same cubic metres. Two flats on different floors sharing a footprint is normal and is deliberately not flagged.
  • Clearance — a basement too close to a tunnel or a main, reported as a distance in metres against the rule.
  • Unassigned floor area — space no unit claims. Some is correct (stairs, lifts); too much means a unit is missing from the record.
  • Containment — a flat outside its own storey, a storey outside its building.
  • Identifier integrity — every object has exactly one, and no two share.

One rule deliberately stays quiet on a plan upload

Unauthorised construction cannot fire when you upload only a plan. With no independent survey there is no evidence about what was actually built, and reporting an offence on an absence of evidence would be a false accusation. That check needs the drone path.

06 · In use

Who touches it, and for what

WhoWhat they doHow
Building-permission clerk Registers a newly sanctioned building — every flat gets an identifier at approval time, not years later Uploads the plan in the 2D → 3D tab
Land-records officer Looks up a property, checks who owns what, reads the validation findings Search box and the 3D viewer. No training beyond clicking.
Metro / utility engineer Asks whether a proposed excavation is clear of anything registered GET /api/column
Survey contractor / state GIS cell Runs the drone pipeline over a whole ward to check what is built against what was sanctioned pipeline.run_pipeline()
Registrar Cites a specific volume in a sale deed instead of “Flat 502, second floor” Quotes the ULPIN, which is checksummed against typos

07 · Command reference

Everything, in order

# --- one-time setup ---
python -m venv .venv
.venv/Scripts/python -m pip install -r backend/requirements.txt

# --- the drone-survey demo (builds its own data, ~30 s) ---
.venv/Scripts/python scripts/build_demo.py

# --- write the sample 2D plans and their drawings ---
.venv/Scripts/python scripts/make_samples.py

# --- start the viewer + API ---
.venv/Scripts/python scripts/serve.py
#   viewer    http://127.0.0.1:8000/
#   API docs  http://127.0.0.1:8000/docs

# --- run the tests (158 of them) ---
.venv/Scripts/python -m pytest -q

Before demonstrating — a real gotcha

If the viewer shows a site you do not expect, an old server is still running and holding the previous register in memory. On Windows, close every Python window, or run: 

Get-CimInstance Win32_Process -Filter "Name like '%python%'" |
  Where-Object { $_.CommandLine -like '*serve.py*' } |
  Stop-Process -Force
