Q1

“What are the security threats, and how will you protect this data?”

Answered by Sanket · technical

Say this · 30 seconds

A land record is a target because it decides who owns what. So we protected the record itself, not only the server. Every identifier is created once and never changes. Every boundary carries a digest, so if the geometry is edited later, the system reports it. Every object says where it came from — surveyed, approved plan, or inferred by AI — and an AI-inferred boundary is never treated as legal proof. And the whole register is validated, so the same cubic metres cannot be given to two owners.

Server ko lock karna easy hai. Record ko khud tamper-evident banana — wahi asli kaam hai.

ThreatWhat stops it todayWhat a deployment adds

Ten validation rules (17 finding types) run over the whole register on every build. These are the ones with a security consequence.

On privacy

We store what a land record already stores and add nothing personal — no Aadhaar, no phone numbers, no financial information. The data sits on the department's own machine.

Do not say

Do not say “fully secure”, “unhackable”, or “blockchain-grade”. Do not claim encryption, login or audit logs — we have not built them, and the prototype's API is open on localhost by design. If the judge notices, own it: “Authentication is a solved problem and the department already has it. A register that cannot tell you when a boundary changed is not solved — that is where we spent our time.”

If they ask about blockchain: the problem here is detection, and a digest already gives us that. A ledger is a deployment choice, not a prerequisite.

Q2

Say this · 30 seconds

It is installed by the land-records department or the municipal corporation, on their own machine — we are the tool, they are the custodian of the data. Q3

“How does this save cost?”

Answered by Himanshu · impact

Say this · 30 seconds

Three ways. First, it removes the largest manual job in cadastral mapping — tracing building footprints by hand — and does it at 98.4 % accuracy against known truth. Second, it needs no new survey: it uses the drone flights SVAMITVA already funds, the 2D layer DILRMP already holds, and the building plans the municipal office already has. Third, and this is the real saving, it catches the errors that would otherwise become court cases.

Sabse bada kharcha survey ka nahi hai — galti ka hai. Aur galti court mein pakdi jaaye, tab tak bahut der ho chuki hoti hai.

The other three savings

  • No licence fee. Every dependency is open source, there are no API keys, and it runs offline on an ordinary laptop. Proprietary 3D GIS is sold per seat, which a tehsil office cannot carry.
  • No new survey for the 2D path. A building-permission office with an approved plan gets a 3D register in under a second, with no drone at all.
  • Disputes prevented, not litigated. An overlap caught by the validator costs seconds. The same overlap found after both deeds are registered costs years.

Do not say

No rupee figures and no multipliers — not “100× faster”, not “saves 6 months per ward”. We have not measured a manual baseline, and a judge who works in land records will know the real number and stop trusting everything else we said.

If they press for a figure: “We can give you the cost structure, not a number we have not measured — the survey is already funded under SVAMITVA, the licence cost is zero, and the operator time is one run per block. The number we did measure is under a minute per block and 98.4 % IoU.”

Q4

“What tech stack are you using, and why that one?”

Answered by Sanket · technical

Say this · 30 seconds

Python for everything that touches geometry, because that is where the geospatial world already lives. FastAPI for the API, because it publishes its own documentation page — that is how another department integrates without a meeting. Shapely for the geometry, which sits on GEOS, the same engine PostGIS uses, so moving to a spatial database later rewrites nothing. The viewer is hand-written WebGL2 with no framework and no CDN, because a tehsil office machine may have no internet. And no deep-learning framework at all — a land record needs a reason, not a probability.

Har layer proven hai. Naya sirf wahi hai jo kahin milta hi nahi — 3D identity aur uska validation.

LayerWhat we useWhy this one
Language Python 3.12 Every serious geospatial library is here, and it is the same world as QGIS and state GIS tooling — a department can hire for it
API FastAPI + Uvicorn, Pydantic Requests are validated by type, /docs is generated automatically for other departments, and the pipeline streams live over SSE
Geometry Shapely 2 (GEOS) Exact polygon operations. Our volumes and clearances are closed-form on top of it, and GEOS is what PostGIS runs — the migration path is already there
Numerics NumPy 2, SciPy The pipeline is array maths over 609,177 points — KD-trees, eigenvalues, least squares
Geodesy Written by us — no PROJ, no pyproj WGS-84 ellipsoid, local ENU, UTM and a 7-parameter Helmert fit, tested to a full ECEF round trip. Keeps installation to one pip install with no GDAL toolchain
Survey file formats laspy (LAS/LAZ), rasterio (GeoTIFF), Pillow The formats a real survey actually arrives in. All three are optional imports — /api/health reports what the installation can read instead of crashing
The AI stages Classical computer vision and statistics — no trained model SMRF ground filtering, DBSCAN clustering, RANSAC planes, facade periodicity. Explainable, no GPU, no labelled Indian-rooftop dataset needed, and every parameter has a physical meaning. An ONNX seam is documented for a trained model later
Viewer Hand-written WebGL2 — 3,304 lines, zero dependencies No npm, no build step, no CDN, so it works offline. We also needed exact control to pick one flat out of a solid stack, which a general 3D library fights you on
Storage JSON document register Correct and fast at demonstration scale. We say out loud that the register class is the seam where PostGIS goes for a city
Tests pytest — 158 tests Every accuracy number we quote is asserted in a test, not printed by a script
Ten packages, all open source, all installable with one command. No cloud account, no API key, no GPU.

What we deliberately did not use

  • No Three.js or any CDN library — the viewer must run on a machine with no internet.
  • No PROJ / GDAL — the classic reason a geospatial tool fails to install in a government office. Ours installs with pip.
  • No PyTorch, TensorFlow or scikit-learn — we cannot put “the model was 87 % confident” in a land record.
  • No cloud service — ownership data stays on the department’s machine.

Do not say

Do not call our pipeline “deep learning” or “a neural network”. It is deterministic computer vision and statistics, and saying otherwise collapses the moment a judge asks what we trained on. Say “computer vision and geometry, with a documented interface where a trained model can be plugged in.”

Do not claim it scales to a whole city today. The JSON store is honest at this scale; PostGIS is the named next step.

  • Re-run AI pipeline — eight stages streaming live, no GPU anywhere.
